# Resource Queue Manager — v1.0.0-rc.2 (pre-release)

**Release candidate for testing — not stable.** The stable v0.4.0
release remains marked Latest. This candidate supersedes v1.0.0-rc.1
and is taken from `release/v1.0.0-rc.2`, not `main`.

## Fixed since v1.0.0-rc.1

- **Home Assistant action editor:** fixed an empty **Resource queue** config
  entry picker showing **Unknown** / **Unknown item**.
- Home Assistant 2026.11's config entry picker requests integration types
  `device`, `hub` and `service`; `helper` entries are excluded.
  Resource Queue Manager now describes each queue as type `service`, so
  the native action field can list configured queues by their title.
- Added a regression test for the picker-compatible integration type
  and four scoped actions (`request`, `release`, `cancel`, `resume`).

The change modifies **only integration classification metadata**.
It does not change the queue domain, `config_entry_id`, saved reservations,
sensor unique IDs, queue capacity, scheduling strategies, or the
semantics of actions. After updating, restart Home Assistant if the
integration manifest remains cached.

## v1 features still under test

- Multiple independent queue instances; FIFO, LIFO, Priority FIFO.
- Per-instance capacity, state persistence, supervised relays, and sensors.
- French and English UI; provider-specific options and request data.
- v0.4 snapshot migration; fail-closed paused startup and explicit resume.
- Multi-instance action routing via `config_entry_id`.

## Safety

Use a separate Home Assistant test installation and noncritical
entities first. Before upgrading an installation that controls heating,
take a full backup and stop related automations. The integration never
physically switches devices and is **not** an electrical safety system.
Rollback should restore the pre-upgrade Home Assistant backup.

The UI fix does not modify fail-closed behavior or provide a shared
global electrical power budget.
