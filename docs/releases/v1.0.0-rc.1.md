# Resource Queue Manager — v1.0.0-rc.1 (pre-release)

**Release candidate for testing — not a stable release.** The production
release **v0.4.0 stays the latest stable version**. This candidate is taken
from the separate `release/v1.0.0-rc.1` branch; the main branch and PR #9
are unchanged.

## What to test

- Multiple independent config entries, separate capacities, storage and sensors.
- Per-entry FIFO, non-preemptive LIFO and Priority FIFO.
- Priority FIFO: values 1–10, high/low order and FIFO ties.
- Per-entry action routing with `config_entry_id`.
- Provider-specific configuration forms, including French translations.
- Persistence, explicit pause/resume, startup recovery and OFF-verified release.
- v0.4 upgrade of a populated FIFO queue.

## Compatibility and risks

This candidate modifies configuration entry behavior and introduces a
mandatory `config_entry_id` on all actions **when multiple queues exist**.
Before creating a second queue, update existing automations with the ID of
their original FIFO entry.

Every queue remains `paused` after setup/reload until explicitly resumed.
Existing active reservations are not preempted. There is no shared electrical
power budget, power measurement or priority aging. The integration never
actuates devices and is **not** an electrical or thermal safety mechanism.

**For safe testing, use a separate Home Assistant installation and noncritical
entities**. Take a full backup of any existing installation first. Do not
install this candidate on a live heating installation without a tested rollback
plan.

A rollback to v0.4 should restore the matching pre-upgrade backup, including
config entries and `.storage`; arbitrary downgrades are not tested.

## Installation

Requires Home Assistant 2026.11 or later. Testers can select this pre-release
in the repository's available release versions if supported by their
Marketplace/HACS client, or download the release archive and copy its
`custom_components/resource_queue_manager` directory to a **test**
Home Assistant installation.

Pre-release availability and automatic update behavior depend on the client.
**Do not expect normal stable users to receive this version automatically.**

## Publication controls

GitHub release tag: `v1.0.0-rc.1` (must target this RC branch). Mark the
release **Pre-release** and **do not set as Latest**. Do not tag `main`,
overwrite `v0.4.0`, or publish `v1.0.0` yet. The tag and GitHub Release
must be created explicitly after the branch's checks pass.
